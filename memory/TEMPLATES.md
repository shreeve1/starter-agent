# Personal Memory Templates

Use Markdown with small YAML frontmatter. Keep entries short and operational: a note is at most 6144 bytes and its `summary` at most 160 characters. Files state only what is true now; git keeps old wording. There is no memory log: the commit message (`memory: <what changed>`) records each change. There are no candidates and no approval step — agents write memory directly when a capture trigger fires, using the templates below.

## Promoted Topic File

```markdown
---
title: Topic Title
summary: One line shown on the index, at most 160 characters
type: preference | doc | voice | email | workflow | context | decision
status: promoted
created: YYYY-MM-DD
updated: YYYY-MM-DD
topics: []
---

## Active memory

- Durable rule or preference.

## Related

- [Related topic](memory/preferences/other-topic.md) - how it relates.

## Notes

- Last reviewed: YYYY-MM-DD
- Changed YYYY-MM-DD: why, only when the reason still matters.
```

## Cross-linking

Memory topics may link to each other with standard markdown links. Use workspace-relative paths that start with `memory/`, for example `[email tone](memory/email/tone-and-format.md)` — the same base `memory/index.md` uses. A link asserts a relationship; the kind of relationship lives in the surrounding prose. Broken links are tolerated — a link to a not-yet-written topic is not an error.

Backlinks ("Cited by") are not stored in files. Compute them at read time by reversing the link graph when it helps retrieval.

## Index

Rows stay link-only (one workspace-relative link per page). Do not add a backlinks column — backlinks are computed at read time. Cross-links between topics live in each topic file's `## Related` section, not here.

Workflows and decisions are not listed per-file here. Each has a generated sub-index — `memory/workflows/index.md` and `memory/decisions/index.md` — built by `python3 .agents/skills/personal-memory/indexes.py` (one `## <topic>` section per topic in `memory/schema.json`); `memory/index.md` carries one `index` row for each sub-index.

```markdown
# Memory Index

## Promoted Memory

| Page | Type | Summary | Updated |
|------|------|---------|---------|

## Client Hubs

| Page | Type | Summary | Updated |
|------|------|---------|---------|
```

One `## Client Hubs` row per `memory/<client_folder>/_hubs/<short>.md` (`gate.py audit` requires it).

## Client Memory Note

Path: `memory/<client_folder>/<subject>/<short>/<slug>.md` (`<client_folder>` is `clients` unless `memory/schema.json` sets `client_folder`). One fact per note. Subjects come from `client_subjects` in `memory/schema.json` (see `README.md`). All six frontmatter keys are required; `gate.py audit` checks them, and checks that `subject`/`client` match the folders.

```markdown
---
type: client-memory
client: acme
subject: 365
title: SharePoint access is via dynamic group "Security Group - Everyone"
verified: YYYY-MM-DD
source: "#70358"              # ticket, "the owner said", or "meeting 7e960c70"
---
One fact in one to three sentences. Link related notes by path.
```

Client hubs (`memory/<client_folder>/_hubs/<short>.md`) are generated by `python3 .agents/skills/personal-memory/hubs.py`; never edit them by hand.

## Decision Memory File

```markdown
---
title: Short Decision Title
summary: One line shown on the index, at most 160 characters
type: decision
status: promoted
created: YYYY-MM-DD
updated: YYYY-MM-DD
topics: [decision]
---

## Decision

One concise summary of what was decided and why.

## Notes

- Prefer role/process summaries over client names unless the client-specific constraint is essential.
- Changed YYYY-MM-DD: why, only when the reason still matters.
```

## Ticket Guide

```markdown
---
title: Short Ticket Guide Title
summary: One-line summary shown on the index
type: guide
status: promoted
created: YYYY-MM-DD
updated: YYYY-MM-DD
last_verified: YYYY-MM-DD
product_vendor: Product or vendor
problem_pattern: Short searchable pattern
risk_level: low | medium | high
source_ticket_id: optional-safe-ticket-id
topics: [ticket-guide]
---

## When to use

One concise description of the reusable ticket pattern.

## Symptoms

- Redacted symptom or error.

## Checks

- Diagnostic check.

## Fix

1. Safe remediation step.

## Verify

- Verification step.

## Notes

- Validation, rollback, source URL, or caution.
```

## glossary.md

Personal entity directory — shorthand → full identity. A single root
file, one row per entity, grouped only under the sections that have content.
Keep entries thin (short form → expansion + a few words of identity); no contact
details or account cruft. Redact per the Safety rules in `README.md`. When first
created, give it its own `index.md` row (it is not in a promoted folder, so
`gate.py audit` will not flag it as missing).

```markdown
---
title: Entity Glossary
summary: Personal entity directory — shorthand → full identity
type: glossary
status: promoted
created: YYYY-MM-DD
updated: YYYY-MM-DD
topics: [glossary]
---

## People
| Shorthand | Identity |
| --- | --- |
| jd | John Doe — Acme IT manager, primary contact |

## Acronyms
| Term | Expansion |
| --- | --- |
| RMM | Remote Monitoring & Management |

## Codenames
| Codename | What |
| --- | --- |
| bluebird | Acme M365 tenant migration |
```


## rules.md

Single routing table at `memory/rules.md`. Precedence bullets at the top, then one row per trigger. Rows hold pointers only.

```markdown
# Rules

- One lead per task. Also load adds content, never steps.
- The more specific When wins the lead.

| When | Lead | Also load | Note |
|---|---|---|---|
| Always | | `memory/preferences/writing.md` | |
| Writing PowerShell | skill `powershell-expert` | `powershell/README.md` | |
```

## Default Promoted Topic Files

- `memory/rules.md` (routing table; template above)
- `memory/email/tone-and-format.md`
- `memory/voice/voice-mode.md`
- `memory/docs/<slug>.md` (one file per subject, e.g. `memory/docs/my-pc-facts.md`)
- `memory/workflows/<topic>/<slug>.md` (e.g. `memory/workflows/memory/session-end.md`)
- `memory/decisions/<topic>/decision-<slug>.md`
- `memory/guides/<product>-<problem>.md`
- `memory/glossary.md` (single file; sections People / Acronyms / Codenames)
- `memory/<client_folder>/<subject>/<short>/<slug>.md` (Client Memory; hubs generated under `memory/<client_folder>/_hubs/`)

Workflows and decisions go in `<topic>/` folders from the `topics` list in `memory/schema.json` (a new topic only with the owner's OK), then `python3 .agents/skills/personal-memory/indexes.py` and `gate.py audit`. 15-file rule: a memory folder holding more than 15 `.md` files directly gets topic subfolders plus a generated index; `gate.py crowded` reports it.
